# 0.3.7 本機 log 格式

正常 ON 使用即記錄，不需要切換診斷模式。設定視窗的「開啟本次 log 摘要」開啟短摘要，完整階段另存於同名主檔。新後端連接建立新檔，舊檔保留在 `%LOCALAPPDATA%\CodexUiaProbe`。

手動回報只需摘要中的「回報碼」和「結果」。不需檔案、截圖、時間或數字列表。以下為格式示例，並非公司測試結果：

```text
回報碼：037-BX-S05
結果：找到按鈕，但按鈕座標為空或無效
```

回報碼格式為 `037-視窗狀態-階段原因`。摘要先列歷史受阻／錯誤、最近一次核准嘗試和各視窗狀態的最後掃描；詳細紀錄只供本機後續查看。後續恢復不刪除歷史紀錄；歷史錯誤不表示現在仍失敗。

| 視窗狀態 | 意義 |
| --- | --- |
| FX / FN | 最大化／一般大小，位於前景 |
| BX / BN | 最大化／一般大小，位於背景 |
| M | 最小化 |
| U | 無法確認，或屬於開關／啟動事件 |

背景由前景 HWND 判斷，不含遮蔽百分比；桌面不可確認不能直接判定鎖定。核准事件使用本次或最後重掃的狀態，並非核准瞬間所有屬性的原子快照。

| 階段原因 | 中文意義 |
| --- | --- |
| S00 | 本次完整掃描沒找到「允許一次」Button；不能判定當時有待核准請求 |
| S01 | 找到符合條件的候選；只代表掃描，不代表呼叫核准 |
| S02 / S03 | 按鈕未啟用／App 未提供 Invoke |
| S04 / S05 / S06 / S07 | 條件未通過／座標無效／中心不在目標範圍／前景按鈕不可見 |
| Bxx / Rxx | 視窗條件阻擋／掃描或驗證未完成；結果行直接寫明原因 |
| E10 / E11 / E12 | 目標視窗／根元素／按鈕祖先鏈變動 |
| E13 / E14 / E15 | 按鈕條件／局部內容／Invoke 能力變動 |
| E17 | 核准前重掃未取得候選；附當次重掃的中文結果與碼 |
| A01 | 已承諾開始一次核准嘗試，還沒有確認結果 |
| A02 | Invoke 返回；不能單憑返回認定 App 工作繼續 |
| A03 / A04 | 原元素失效／在前景下隱藏，工具結束本次觀察 |
| A05 | 前一候選尚未離開或同一候選已處理，不重送 |
| A06 / A07 | 結果未確認／嘗試開始後錯誤，可能已生效，不重送 |
| T01 / T02 / T03 | 初次掃描／核准前重掃／核准或觀察逾時 |
| G01 / G02 | ON／OFF 或開關已改變 |

`Bxx`、`Rxx` 的尾碼：00 其他讀取、01 原生狀態、02 隱藏、03 系統 cloak、04 互動桌面、05 根視窗狀態、06 frame、07 modal 阻擋、08 掃描中切換、09 根元素讀取、10 WindowPattern、11 控制項屬性、12 父層／局部內容、13 節點上限、14 深度上限、15 樹重複、16 多候選。不需背代碼，直接轉抄結果文字即可。

完整紀錄中每筆有 L 序號和 P 候選編號。P 只是在同一後端執行期間，依 UIA 候選識別與可觀察的離開週期建立的本機序號，不是 App 原生請求 ID；UIA 重用元素或缺少離開訊號時無法可靠區分每次業務請求。沒有候選就明確標示未建立關聯，不把先前 P 編號套到未知工作。

log 僅含工具固定文字、本機時間、視窗狀態和有界計數。命令、對話、標題、PID、路徑、UIA RuntimeId 與局部內容指紋不寫入。這項紀錄改造不代表完全遮蔽、最小化或鎖定問題已修復。
