# Codex Auto-Accept Desktop 0.3.7

Windows 系統匣常駐工具。雙擊 `CodexAutoAcceptDesktop.exe` 使用，不需開啟或保留 Windows Terminal。每次啟動都是 OFF，由使用者手動開啟 ON。

## 這版的變更

畫面上的診斷區、數字列表和唯讀診斷按鈕已移除。正常開 ON 使用時，自動將中文紀錄與短摘要寫入本機。設定視窗新增「開啟本次 log 摘要」，可稍後查看，不需停住工作、保留核准畫面或記住核准時間。

摘要先列出回報碼與中文結果；詳細 log 分開記錄掃描、核准前重掃、開始嘗試、呼叫返回和結果觀察。同一 UIA 候選用本機 P 編號關聯；讀不到候選時明確寫「未建立可追蹤候選」，不猜測是哪次工作。相同狀態的重複掃描合併，已寫下的紀錄不會因之後恢復而刪除。

**這版沒有宣稱修好完全遮蔽、最小化或鎖定。** 公司最新回報 0.3.6 在 App 最大化且被完全蓋住時不能核准，最小化也不能。先前將完全遮蔽視為已驗收的結論已撤回。已確認的是 0.2.1 持續 ON／OFF，以及 0.3.2 一般使用者連接和基本核准；解鎖後會自行恢復是使用者回報，不能推論鎖定期間可用。

2026-10-13 公司 0.3.7 實測仍是背景、最小化有核准請求但不會 auto-accept，鎖定未測。公司三種 Codex 介面只能「請求核准」，不能依賴 Approve for me／Full Access。另一台 Windows 11 的驗證交接在 repository 的 `desktop-probe/WINDOWS_HANDOFF.md`，目前不將個人測試機與公司版本混為同一驗收。

## 更新與使用

1. 在舊工具的系統匣右鍵選「退出」；若 console 版仍在執行，按 Q 結束。
2. 完整解壓新版到新目錄，保留所有 EXE 與 config 在同一資料夾。
3. 以一般使用者身分雙擊 `CodexAutoAcceptDesktop.exe`。
4. 選擇 App 視窗，連接後手動開啟 ON；關閉設定視窗仍留在系統匣。

更新工具不需停止正在執行的 App 工作。不要只替換前端 EXE；後端 `CodexUiaManualInvoke.exe` 必須使用同一版本。若曾啟用登入啟動，搬移目錄前在舊版取消勾選，再到新版設定。

系統匣右鍵可切 ON／OFF、開啟設定或退出。綠色表示後端已回報 ON，灰色表示 OFF／等待 App，橘色表示後端停止。重開工具一定回到 OFF。切 OFF 停止新的核准嘗試，已承諾開始的一次操作可能仍完成。

## log 與手動回報

設定視窗按「開啟本次 log 摘要」，會用本機預設文字編輯器開啟摘要；不開啟 Terminal、不上傳或複製到剪貼簿。完整紀錄與摘要都在：

```text
%LOCALAPPDATA%\CodexUiaProbe\
  auto-日期-時間-隨機碼.txt           完整階段紀錄
  auto-日期-時間-隨機碼-summary.txt   回報用短摘要
```

每次連接後端會建立一組新檔案；重新連接不會刪除前一組，可在資料夾稍後查看。啟動及 ON／OFF 也有紀錄；一般 OFF 不掃描 App。紀錄無法寫入時，不繼續該次尚未呼叫的核准；後端異常停止時需人工重新連接。

若要回報，手動轉抄摘要中的兩行即可：

```text
回報碼：037-BX-S05
結果：找到按鈕，但按鈕座標為空或無效
```

以上是格式示例，**不是公司測試結果**。`BX` 已包含「最大化／背景」狀態，不需再抄時間或數字列表。最近一次受阻標示為歷史紀錄；後續成功不會證明之前沒有失敗。沒有找到按鈕也不能證明當時有待核准請求。

log 只寫工具固定文字、本機時間、原生視窗狀態與計數。不保存命令、對話、視窗標題、PID、程序路徑、RuntimeId 或內容指紋，不新增網路傳輸。P 編號是本機 UIA 候選序號，**不是 App 的原生核准請求 ID**。背景只代表不是前景，並不表示已確定被完全遮蔽；工具目前也沒有明確的系統鎖定事件判定。代碼說明在 ZIP 的 `LOG_FORMAT.md`。

## 連接、登入啟動與核准範圍

工具記住所選 App 的執行檔路徑，找到唯一符合的視窗後可連接；路徑讀取受限或有多個視窗時需手動選擇。App 正常重開可保留本次工具的 ON 意圖；後端異常或逾時則停止，由使用者檢查 App 後重新連接，回到 OFF。

「登入 Windows 時啟動」預設不勾選，只設定目前使用者的 Run 值。公司政策禁止時仍可手動啟動。不建立管理員服務或排程；前後端為 asInvoker，未要求提權。Windows 需 .NET Framework 4.8／4.8.1，且公司允許兩支 EXE 執行；成品未經 Authenticode 簽署。

ON 處理所選視窗內唯一、精確名為「允許一次」、已啟用且具 Invoke 的 Button，核准前完整重掃並比對目標、祖先鏈與局部內容；每個可辨識的核准週期最多嘗試一次。不具有命令規則或聊天 ID 綁定，切換聊天也會改變監聽對象。無法確認舊候選已離開時會等待，不重送不確定的操作。

選用的「測試背景相容啟動」仍保留既有實驗功能，本版沒有加入新參數，也沒有證實公司版本支援。日常紀錄不需使用此功能；它需要先自行完整退出 App，不適用於持續中的工作。工具不會替你關閉、還原或搶前景。

設定存於 `%LOCALAPPDATA%\CodexAutoAcceptDesktop\settings.json`，包含所選 App 路徑和引擎線索，不含 ON 狀態。移除時先取消登入啟動、系統匣退出，再刪除解壓目錄；需要時另刪本機設定與紀錄資料夾。

## 驗證範圍

本版在 macOS 交叉建置 Windows net48 成品，執行可攜邏輯測試與編譯產物 API 檢查。實際 Windows UIA provider、WinForms、文字編輯器開檔與公司桌面狀態未在此主機執行，不能以這些檢查宣稱背景核准通過。詳細紀錄在 `VERIFICATION.md`，原始碼在 `source/`。
