# Codex Auto-Accept Desktop 0.3.10（候選測試版）

Windows 系統匣常駐工具。雙擊 `CodexAutoAcceptDesktop.exe` 使用，不需開啟或保留 Windows Terminal。每次啟動都是 OFF，由使用者手動開啟 ON。

## 這版的變更

此 ZIP 是 0.3.10 的 R11 本機候選。核准後端使用同一個 `CUIAutomation8` 用戶端取得元素、掃描、重驗與 Invoke，設定並讀回 `AutoSetFocus=false`，呼叫前再次確認；無法確認設定時停止，不退回可能自動取得焦點的舊用戶端。原有唯一精確「允許一次」Button、完整重掃、目標／祖先／局部內容確認、ON／OFF 代次與每個週期最多一次 Invoke 均保留。

2026-10-14 在本機 App `26.1007.2314.0` 完成 24 個真實背景／最小化案例，涵蓋部分遮蔽、一般大小完全遮蔽、最大化完全遮蔽及最小化，各含既有／新請求各三案。全部在 20 秒內完成 marker；獨立 Windows 前景／焦點事件與原生狀態觀察未記錄到 App 搶焦點，六個最小化案例全程保持最小化。另通過前景與 OFF 回歸。本輪未重啟 App；公司版本與鎖定仍未驗證，詳見 `WINDOWS_TEST_RESULTS_20261014_R11.md`。

下列 R4／R5 段落保留較早候選的結果，包含當時的新請求失敗與轉前景，不能與 R11 合併計算。

修正核准後觀察的例外分類。0.3.9 的同一個例外處理區塊包含原候選與根元素／WindowPattern 讀取；後者發生 `ElementNotAvailableException` 時，可能被誤當成原核准按鈕失效而結束去重週期。本版將根元素讀取移出候選失效的處理區塊，透過共用的觀察步驟保留讀取順序與五秒觀察期限。根元素或 WindowPattern 失效改由既有 A07「核准後結果觀察」記錄，結果未知時維持舊候選的去重狀態。切 OFF 撤銷尚未開始嘗試的舊代次，但不清除未知結果，也不重送已開始的一次操作。

只有原候選的身分或屬性讀取失效，才可使用自動模式 A03 的原元素失效判定；既有前景隱藏判定仍保留。production 固定辨識 UIA 的 `ElementNotAvailableException`，其他例外不會被泛稱為候選消失。唯一精確「允許一次」Button、完整重掃、目標／祖先／局部內容確認、持續 ON 及每個週期最多一次 Invoke 均未放寬。

以下本機紀錄改進沿用 0.3.9：

修正主 log／短摘要寫入的拒絕存取與安全性例外未分類問題。以實際 Windows 唯讀檔案重現：舊版拋出未分類的 `UnauthorizedAccessException`；本版分別辨識主檔、摘要暫存、摘要取代階段。完整主檔無法寫入時停止新嘗試；短摘要失敗而主檔可寫時保留固定原因並繼續。僅在 HRESULT 明確含 Win32 錯誤碼時記錄數字，其餘寫「未確認」，不寫原始例外訊息。

相同掃描與等待狀態滿十秒後，下一次完成掃描或等待事件留下新紀錄；ON 後首筆掃描重新記錄。這是紀錄節流，provider 卡住時不保證每十秒輸出。核准嘗試開始後的錯誤分開記錄 Invoke 前後原生查詢、Invoke 呼叫、返回紀錄與結果觀察階段，結果未知仍不重送。沒有新增畫面診斷區、數字列表或需手動抄寫的流程。

沿用 0.3.8 的首次選視窗按鈕修正與 AnyCPU 建置設定，前後端必須使用同一版本。

主 log 新增核准呼叫返回後的原生視窗狀態（A08），區分仍在背景、仍為最小化及已轉為前景。主檔寫入、摘要暫存寫入、摘要原子取代分別記錄 L01–L03 與本機檔案錯誤代碼。短摘要遇到 Windows 暫時分享衝突時，最多重試四次、每次等待 100 毫秒；不重試主檔附加或核准操作。短摘要仍失敗時，將原因附加到完整主檔並繼續監聽；主檔無法寫入才停止新嘗試。摘要可能過期，應保留完整主檔。

2026-10-13 的 R4 已重新確認原生 Computer Use 可讀取並操作專用工具。修改前以未修改的 0.3.9 測試：前景一次開 ON 後，三筆不同真實請求均完成各自 marker，工具維持 ON；App 完全遮蔽後才產生的新請求，三案各自 20 秒觀察期內均未完成。完整主 log 為一般大小背景的 S00，沒有精確核准 Button；還原前景後才完成。此失敗發生在候選建立前，與本版修正的核准後觀察分類不同，尚未證實根因。

0.3.10 的 R5 已完成稽核初始 OFF、前景一次 ON 三案、部分遮蔽兩種順序各三案，以及一般大小／最大化完全遮蔽既有請求各三案；遮蔽完成案的 A08 均為返回後轉前景，不能當成全程背景成功。最小化既有請求三案有獨立 marker 且返回後仍最小化，A06／A05 保留 UIA 未知結果與舊候選去重，沒有重送。一般大小／最大化完全遮蔽與最小化後的新請求各三案，在正式 20 秒均無 marker／A01，完整主 log 的精確 Button 為零，還原前景後才完成。切 OFF 保留新請求、重啟與連接後仍 OFF 也通過；重啟案的請求早於重啟，不能當成重啟後新請求。**本版未修好背景／最小化新請求，鎖定未測，未以程式檢查替代真實驗收。**

相容冷啟動的唯讀 preflight 通過，one-shot armed 後只記到等待退出；代理執行 GUI「結束 ChatGPT」使控制會話中斷，沒有 launch stage 或相容 profile 真實矩陣，列 BLOCKED。使用者回報 App 被代理關閉，代理已承認，沒有歸咎使用者。後續同路徑 App 的四個既有旗標均未出現，helper 不在執行；不猜退出碼、精確退出時點或新 App 啟動來源，保留單次 ledger 不重試。目前 App 開啟，最後已在工具 OFF 後只停止本輪前後端、恢復原設定並核對位元組／雜湊相符，測試資料與 raw log 留在本機。歷史矩陣畫面直接觀察來自本會話 Computer Use 輸出，沒有另存本機截圖檔；不能以它們宣稱已有截圖備份或可回放。

本機 App 套件 `26.1007.2314.0` 與公司 `26.803.81509` 不同。R4 矩陣及限制見 `WINDOWS_TEST_RESULTS_20261013_R4.md`；`WINDOWS_TEST_RESULTS_20261013_R3.md` 保留當時的工具授權拒絕與證據更正，`WINDOWS_TEST_RESULTS_20261013.md` 保留更早歷史，不將不同輪次或版本的觀察合併成驗收。

## 0.3.7 的介面與公司回報

畫面上的診斷區、數字列表和唯讀診斷按鈕已移除。正常開 ON 使用時，自動將中文紀錄與短摘要寫入本機。設定視窗新增「開啟本次 log 摘要」，可稍後查看，不需停住工作、保留核准畫面或記住核准時間。

摘要先列出回報碼與中文結果；詳細 log 分開記錄掃描、核准前重掃、開始嘗試、呼叫返回和結果觀察。同一 UIA 候選用本機 P 編號關聯；讀不到候選時明確寫「未建立可追蹤候選」，不猜測是哪次工作。相同狀態的重複掃描合併，已寫下的紀錄不會因之後恢復而刪除。

**這版沒有宣稱修好完全遮蔽、最小化或鎖定。** 公司最新回報 0.3.6 在 App 最大化且被完全蓋住時不能核准，最小化也不能。先前將完全遮蔽視為已驗收的結論已撤回。已確認的是 0.2.1 持續 ON／OFF，以及 0.3.2 一般使用者連接和基本核准；解鎖後會自行恢復是使用者回報，不能推論鎖定期間可用。

2026-10-13 公司 0.3.7 實測仍是背景、最小化有核准請求但不會 auto-accept，鎖定未測。公司三種 Codex 介面只能「請求核准」，不能依賴 Approve for me／Full Access。另一台 Windows 11 的驗證交接在 repository 的 `desktop-probe/WINDOWS_HANDOFF.md`，目前不將個人測試機與公司版本混為同一驗收。

## 更新與使用

1. 在舊工具的系統匣右鍵選「退出」；若 console 版仍在執行，按 Q 結束。
2. 完整解壓新版到新目錄，保留所有 EXE、config 與 `Interop.UIAutomationClient.dll` 在同一資料夾。
3. 以一般使用者身分雙擊 `CodexAutoAcceptDesktop.exe`。
4. 選擇 App 視窗，連接後手動開啟 ON；關閉設定視窗仍留在系統匣。

更新工具不需停止正在執行的 App 工作。不要只替換前端 EXE；後端 `CodexUiaManualInvoke.exe` 必須使用同一版本。若曾啟用登入啟動，搬移目錄前在舊版取消勾選，再到新版設定。

系統匣右鍵可切 ON／OFF、開啟設定或退出。綠色表示後端已回報 ON，灰色表示 OFF／等待 App，橘色表示後端停止。重開工具一定回到 OFF。切 OFF 停止新的核准嘗試，已承諾開始的一次操作可能仍完成。

## 本機 log

設定視窗按「開啟本次 log 摘要」，會用本機預設文字編輯器開啟摘要；不開啟 Terminal、不上傳或複製到剪貼簿。完整紀錄與摘要都在：

```text
%LOCALAPPDATA%\CodexUiaProbe\
  auto-日期-時間-隨機碼.txt           完整階段紀錄
  auto-日期-時間-隨機碼-summary.txt   回報用短摘要
```

每次連接後端會建立一組新檔案；重新連接不會刪除前一組，可在資料夾稍後查看。啟動及 ON／OFF 也有紀錄；一般 OFF 不掃描 App。完整主檔無法寫入時，不繼續該次尚未呼叫的核准；後端異常停止時需人工重新連接。短摘要失敗會記到主檔，後續仍使用主檔觀察，不要求停住工作或手動抄寫。

以下為本機紀錄的格式：

```text
回報碼：0310-BX-S05
結果：找到按鈕，但按鈕座標為空或無效
```

以上是格式示例，**不是公司測試結果**。`BX` 已包含「最大化／背景」狀態，不需再抄時間或數字列表。最近一次受阻標示為歷史紀錄；後續成功不會證明之前沒有失敗。沒有找到按鈕也不能證明當時有待核准請求。

log 只寫工具固定文字、本機時間、原生視窗狀態與計數。不保存命令、對話、視窗標題、PID、程序路徑、RuntimeId 或內容指紋，不新增網路傳輸。P 編號是本機 UIA 候選序號，**不是 App 的原生核准請求 ID**。背景只代表不是前景，並不表示已確定被完全遮蔽；工具目前也沒有明確的系統鎖定事件判定。代碼說明在 ZIP 的 `LOG_FORMAT.md`。

## 連接、登入啟動與核准範圍

工具記住所選 App 的執行檔路徑，找到唯一符合的視窗後可連接；路徑讀取受限或有多個視窗時需手動選擇。App 正常重開可保留本次工具的 ON 意圖；後端異常或逾時則停止，由使用者檢查 App 後重新連接，回到 OFF。

「登入 Windows 時啟動」預設不勾選，只設定目前使用者的 Run 值。公司政策禁止時仍可手動啟動。不建立管理員服務或排程；前後端為 asInvoker，未要求提權。Windows 需 .NET Framework 4.8／4.8.1，且公司允許兩支 EXE 執行；成品未經 Authenticode 簽署。

ON 處理所選視窗內唯一、精確名為「允許一次」、已啟用且具 Invoke 的 Button，核准前完整重掃並比對目標、祖先鏈與局部內容；每個可辨識的核准週期最多嘗試一次。不具有命令規則或聊天 ID 綁定，切換聊天也會改變監聽對象。無法確認舊候選已離開時會等待，不重送不確定的操作。

選用的「測試背景相容啟動」仍保留既有實驗功能，本版沒有加入新參數，也沒有證實公司版本支援。日常紀錄不需使用此功能；它需要先自行完整退出 App，不適用於持續中的工作。工具不會替你關閉、還原或搶前景。

設定存於 `%LOCALAPPDATA%\CodexAutoAcceptDesktop\settings.json`，包含所選 App 路徑和引擎線索，不含 ON 狀態。移除時先取消登入啟動、系統匣退出，再刪除解壓目錄；需要時另刪本機設定與紀錄資料夾。

## 驗證範圍

R11 的三個建置、十一組測試與三項 API 稽核通過；新增焦點設定失敗、讀回為 true、設定變更與讀回例外的停止測試。靜態稽核只准許一個 COM Invoke 參考、`CUIAutomation8`、焦點設定／讀回及明列的唯讀 COM 成員；另用含舊 managed Invoke 的組件確認稽核會拒絕。靜態稽核與真實 App 的 24 案結果分開保留。

R11 的完整主 log 均可寫入；隔離紀錄路徑的短摘要原子取代出現既有 L03／Win32 3，摘要不列為通過。背景 UIA 核准後觀察保留 A06「結果未確認」與去重，實際工作完成由獨立 marker、命令退出碼及聊天完成紀錄確認，未將 A02／A08 當成工作成功。下方為較早候選的程式驗證與歷史限制。

本版在 Windows 執行 `scripts/check-desktop.ps1`，三個 net48 建置、十一組測試及三項 API 檢查通過，退出碼 0。包含共用觀察步驟與真正 AutoGate 的回歸，以及沿用的 Windows 檔案共用／唯讀例外測試。另有 21 項 Windows net48 檢查，直接連結 production 共用觀察步驟並使用真正 UIA 例外；只檢查程式處理，不讀取 App/provider、不呼叫 Invoke。建置有 NU1900 套件弱點資料來源不可達警告，測試有既有 CS0649 警告；不是零警告。

R4 已能以 Computer Use 操作 0.3.9 基準，R5 已完成上述 0.3.10 普通使用者工作階段矩陣稽核；完全遮蔽／最小化後新請求仍失敗。相容冷啟動因控制中斷為 BLOCKED，公司版本與鎖定未測。實際測試狀態以 `WINDOWS_TEST_RESULTS_20261013_R4.md` 為準，成品封裝另行核對。程式檢查範圍在 `VERIFICATION.md`，原始碼在 `source/`。
