## 方法與判定

專用測試聊天只以 `exec_command`、`sandbox_permissions=require_escalated`、個別 justification、無 prefix rule，向 App 提出真實核准請求。這是 App 的請求核准，不是 Windows 提升權限。控制工作與產生請求的聊天分開；請求透過已授權的聊天訊息工具送到測試聊天，不需把 App 帶回前景。

每次操作只寫入並讀回 `C:\Temp\codex-autoaccept-validation-20261013\markers` 下的獨立 marker。由測試聊天的等待核准狀態、完整主 log、獨立 marker 與聊天後續完成結果交叉確認。找到候選、P 編號或 Invoke 返回均不單獨算成功。

一般大小為 1280×820；部分遮蔽視窗為 602×462，位置約 (507,100)。完整覆蓋視窗為 1920×1152，原點 (0,0)；最大化 App 亦為 1920×1152。Computer Use 的 `activate_window` 會將最大化視窗還原，因此完整覆蓋必須在啟用遮蔽視窗後明確最大化並重新核對範圍。

新版核心案例均在確認真實請求後另觀察 20 秒；期間不人工核准、不直接 Invoke、不還原或切回 App。原版有較長的分段觀察，後來覆蓋重測的部分計時從覆蓋建立時開始；不是完全相同的效能計時基準。未遇到本次 UIA provider 45 秒期限到期，未無限等待。

以下 PASS 表示該列所述操作有證據成立。遮蔽列即使 marker 完成，若 Invoke 後 App 自己轉前景，**不能解讀為全程留在背景成功**。恢復後才完成另外記錄。人工處理與等待期限後的 marker 不計入背景期間完成數。
